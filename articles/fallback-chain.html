降级链：
AI 应用活在生产环境的底线

关联 反诈骗 AI 援助平台 · 可交互 Demo 见「实验」 主题 可靠性工程 · LLM 应用

8 月 7 日，行动报告页面卡死。用户点「生成报告」，转圈，永远转圈。排查结果是个很小的根因：下游返回的 runId 发生漂移，前端拿着旧 id 轮询，永远等不到它要的结果——无限轮询。小根因，大症状，这类事故教我的东西比任何架构文档都多。

那天我连发了四个修复：修漂移、把两个串行阶段并发（100s 到 25s）、轮询加 3 分钟超时兜底、结构化输出的重试链做异常分层。修完之后我意识到真正的题目不是这四个补丁，而是：AI 应用活在生产环境，靠的不是它最好的时候有多好，而是它最坏的时候坏到哪。这条「最坏的时候」的路径，就是降级链。

一、先承认：LLM 是个不稳定的依赖

传统软件的依赖（数据库、缓存、下游服务）已经有一整套可靠性词汇：超时、重试、熔断、舱壁。LLM 应用把依赖列表加了一行性质完全不同的条目——一个会漂移、会限流、会幻觉、会突然变慢三十倍的黑盒。它不稳定的方向还不一样：限流是快速失败，超时是慢慢失败，内容过滤是看心情失败。

所以 LLM 应用的第一性原理和传统可靠性工程是同一句话：每个依赖都要有「失败时的样子」。不是「希望它不失败」，是提前设计好它失败之后用户看到什么、系统进入什么状态、多久之后尝试恢复。

二、一条请求的四条命

把这句话落到实处，我在报告生成链路上画了一条显式的降级链。滚下来看——每一层都是「上一层失败时的样子」：

L1主链路：结构化输出 + 分层重试

主模型 + 结构化输出约束。重试按异常类型分层：限流类退避重试、格式错误类带着错误信息重问、内容过滤类不重试直接降级——因为重试解决不了价值观拒绝。分层是为了防「重试放大」：一次失败重试三次，超时再各重试三次，链路末端就是 3×3=9 倍延迟，这就是 8 月 7 日差点发生的事。

L2备选模型：同格式换引擎

主模型不可用时切换备选。关键约束是输出 schema 必须在两层之间完全一致——降级的意义是下游无感，如果换模型要换解析逻辑，那不是降级，是第二套系统。备选层也要有自己的超时，不许它比主层更拖。

L3缓存与模板：昨天能用的今天还能用

同类案件的近期报告缓存命中，直接给「相似案例参考」并明确标注生成时间；模板兜底则输出结构完整但字段留白的报告，让用户填关键项。宁可给一个诚实的半成品，不给一个自信的废品。

L0底线：错误页 + P0 上报 + 自动恢复

全链失败时用户看到的是一句人话（「报告生成遇到问题，已记录，稍后重试」）而不是白屏或无限转圈；错误带上下文进 P0 上报；页面具备自动恢复——故障修复后用户无需刷新。这条来自一次真实事故：浏览器自动翻译插件把页面 DOM 改坏导致整页崩溃，那次的修复（禁译 + 全局错误页 + 自动恢复）后来成为所有页面的标配。

三、行业词汇表：你不是第一个遇到的人

降级链的每个环节在可靠性工程里都有成熟名字，LLM 应用不必发明，只需对号入座：

  • 断路器（Circuit Breaker）：Hystrix 时代的老将，Envoy、Resilience4j 至今在用。连续失败到阈值就「跳闸」，一段时间内直接走降级路不再撞墙。LLM 场景的翻译：某个模型连续超时，就先切备选，别让用户替你等它回心转意。
  • 重试预算（Retry Budget）：全局限制重试占比，防止「大家都在重试」的雪崩。8 月 7 日教训的正式学名。
  • 超时分层（Timeout Budget）：整条链路的超时要按层分配且总和小于用户侧上限——外层 30 秒，内层就不许各设 29 秒。
  • 优雅降级（Graceful Degradation）：Web 前端的老传统——JS 挂了 HTML 还在。对应到 AI 产品：模型挂了，产品还剩什么？能浏览历史、能看缓存、能手动填模板，就是还活着。
  • 舱壁隔离（Bulkhead）：把资源分舱，一舱进水不沉全船。AI 应用里的翻译：报告生成和会话服务用独立的模型配额与队列，别让一个重任务把轻交互全堵死。

四、降级三定律

把这些攒成可以贴在工位上的三条：

  • 显式：降级路径画在架构图上、写在代码里，不许「到时候再说」。每层触发条件和出口状态有名字、有编号，和正常链路同一级别的代码待遇。
  • 可观测：每层降级都要留下痕迹——哪次请求走到了哪层、为什么。降级静悄悄地发生，等于系统在带病上班而你不知道。这也是我把「报告可观测性」和重试、分层一起做的原因（那次是 PR #30）。
  • 可测试：降级路径要能演练。故障注入不是 SRE 的专利，砍掉模型 API key 跑一遍集成测试，看看系统是按设计降级还是原地爆炸——炸了 better now than in production。

五、底线的哲学

最后说点价值观。做 AI 应用的人容易把注意力全放在能力上限——更强的模型、更巧的 prompt、更炫的 Agent。但用户信任的建立方式恰好相反：上限决定用户为什么来，底线决定用户还来不来。反诈骗援助场景里，一个受骗后来求助的用户，看到无限转圈的耐心是零。

降级链不是悲观主义，是诚实主义：承认依赖会失败，承认自己会犯错，然后把每一种失败都安排好体面的下场。系统真正的可靠性，藏在它最坏的那一刻里。

我把这条链做成了可交互的 Demo（见导航「实验」），你可以亲手掐断每一层，看请求怎么走、用户看到什么。可靠性这东西，讲十遍不如亲手弄坏一遍。
